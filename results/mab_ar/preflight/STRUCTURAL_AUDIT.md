## Scope

In scope, per the paper's MAB-AR setting: **EventQA, RULER QA1, RULER QA2**.

Excluded by design: MemoryAgentBench's own LongMemEval category (`longmemeval_s`,
`longmemeval_s*`), DetectiveQA, FactConsolidation, TTL/ICL, Recsys, InfBench. The paper
evaluates LongMemEval-V2 separately; including MAB's older LongMemEval copy inside MAB-AR
would create source overlap between two reported settings.

## 7. Query/answer identifier fields

Native metadata keys present on every AR sample: `demo`, `haystack_sessions`, `keypoints`,
`previous_events`, `qa_pair_ids`, `question_dates`, `question_types`, `question_ids`,
`source`.

`qa_pair_id` is present for every query (e.g. `eventqa_full_no0`, `ruler_qa1_197K_no0`).

**`qa_pair_id` is unique only within a history, not within a source.** All five EventQA
histories reuse the identical id list `eventqa_full_no0 … eventqa_full_no99`. Any log keyed
on `qa_pair_id` alone would silently collapse five distinct books' queries onto one another.
The integration therefore keys every record on the composite
`history_id :: query_index` and stores `qa_pair_id` as a non-unique attribute.

MAB has no native context/history identifier, so `history_id` is synthesized as
`<source>::h<sample_index>` over the deterministically ordered upstream filtered dataset.

## 8. Does one source history carry multiple queries?

Yes — 100 queries per history for all three sources, uniformly. This is what forces the
history-level exchangeability rule: the 700 queries are **not** 700 independent units.

## 9. Does the same source history appear more than once?

Not within the in-scope sources: all 7 contexts are distinct (no duplicate SHA-256), and
no context is shared across the three sources.

But the split does contain the same histories again under other source names.
`eventqa_131072` and `eventqa_65536` were verified to be **strict character prefixes** of
the same five `eventqa_full` books:

```
book 0: full=2,306,899 chars   128k=573,520 (prefix of full)   64k=285,324 (prefix of 128k)
book 1: full=3,171,853 chars   128k=567,840 (prefix of full)   64k=285,199 (prefix of 128k)
book 2: full=2,591,136 chars   128k=569,210 (prefix of full)   64k=279,622 (prefix of 128k)
book 3: full=1,694,961 chars   128k=548,401 (prefix of full)   64k=272,813 (prefix of 128k)
book 4: full=1,957,500 chars   128k=566,706 (prefix of full)   64k=282,936 (prefix of 128k)
```

Their question sets differ from `eventqa_full`'s, so they are *not* duplicate rows — but
the underlying long-memory source is the same book. Treating a truncation as an additional
independent history would place one book in more than one partition, which is precisely the
leakage the brief forbids. They are therefore **not** counted as extra histories.

## 11–13. Native evaluation

| source | upstream branch of `utils.eval_other_utils.post_process` | accuracy field | LLM judge |
|---|---|---|---|
| EventQA | `_process_eventqa_dataset` | `substring_exact_match` | none |
| RULER QA1 | `_process_ruler_memory_merging_dataset` → `default_post_process` | `substring_exact_match` | none |
| RULER QA2 | `_process_ruler_memory_merging_dataset` → `default_post_process` | `substring_exact_match` | none |

`substring_exact_match` =
`drqa_metric_max_over_ground_truths(substring_exact_match_score, prediction, gold)`, i.e.
`normalize_answer(gold) in normalize_answer(prediction)` maximised over the gold list, where
`normalize_answer` lowercases, strips punctuation, drops `a|an|the`, and collapses whitespace.
This matches the README's AR mapping. It is binary in {0, 1}.

`_process_eventqa_dataset` additionally emits `eventqa_recall`; the README does **not** use
it for AR accuracy, and it is not used here. No AR source requires an LLM judge; none of the
three touches `llm_based_eval/`.

Because the label is binary, `gamma = 0.5` produces exactly `R = 1[correct]`. Gamma is
retained for cross-setting consistency and documented as a no-op on this metric.

## 14. Is any answer or query injected into memory during evaluation?

No. Upstream MAB streams the context with `send_message(chunk, memorizing=True)` and then
evaluates with `send_message(query, memorizing=False)`; the `memorizing=False` path never
writes to the host. The ReCoverMem runner reproduces that contract and additionally asserts
that the host's memory count is unchanged across the entire query phase of a history.

## Exchangeability rule in force

The independent statistical unit is the **source history**. For history *i* with *T_i*
queries:

```
FS_i(tau)  = (1/T_i) sum_t 1[s_it >= tau AND R_mem,it = 0]
Cov_i(tau) = (1/T_i) sum_t 1[s_it >= tau]
```

with histories averaged equally. Queries from one history are never split across
`predictor_train` / `calibration` / `final_test`.

Since every AR history has exactly *T_i* = 100 queries, history-equal and query-equal
weighting coincide numerically here — but the *number of independent units* is 7, not 700,
and that is what the calibration guarantee depends on. See
`results/mab_ar/preflight/FEASIBILITY_GATE.md`.
